# Экран практики: бриф, четыре направления и макеты

Дизайн-исследование для курса Go Backend, 13 октября 2026 года. Здесь шаги 1-3 процесса: бриф, концепции, макеты. Систему (шкала шрифтов, токены, состояния), бренд-материалы и финальные тексты делаем после выбора направления.

Смотреть с `index.html`: это страница сравнения со ссылками на четыре макета. Файлы открываются двойным щелчком, сборка не нужна. Как устроена практика у других курсов, разобрано в `research.md` (его писал агент `product-analyst`).

## Шаг 1. Бриф

**Запрос владельца.** Предложить UX/UI и логику продукта так, чтобы механика была понятной; показать курс так, чтобы он ощущался практикой; сделать проще и удобнее; 3-4 макета.

**Аудитория.** В PROJECT.md она не записана («уточнить у владельца»). Макеты исходят из допущения: взрослый новичок, который учится после работы, заходит на 30-40 минут, часть заходов делает с телефона, а код пишет на своём компьютере. Если это не так, пересматривать нужно в первую очередь макет 3.

**Единственная задача экрана.** Ученик в середине спринта за пять секунд понимает, что ему делать прямо сейчас, и видит, сколько проекта уже работает.

**Что не так сегодня.**

1. Нет одного очевидного следующего действия: путь идёт через кабинет, модальное окно, тему, урок и ещё пять вкладок спринта.
2. Чтение стоит перед делом: одиннадцать уроков теории до первой строки кода проекта.
3. Прогресс считается в прочитанных уроках. 41 проверка и commit ученика на сайте не видны до самой сдачи.
4. Доску ученик двигает руками, с результатами проверки она не связана.
5. На странице много текста, с телефона её трудно просмотреть.

**Ограничения.**

- Светлая тема, индиго `#4b3aeb`, токены из `src/styles-light.css`. Шрифты приложения: Manrope и Roboto Mono. Направления отличаются механикой и раскладкой, бренд один.
- У сайта нет сервера. Код ученика запускает GitHub Actions в его репозитории, сайт читает открытый API GitHub. «Статус из твоего репозитория» возможен, «платформа запускает твой код» невозможна, и тексты не должны на это намекать.
- Менторов, ревью и дедлайнов нет. Всё бесплатно, цен и замков в макетах нет.
- Задача приходит от роли «Тимлид». Имён, компании, сюжета и иллюстраций героев нет.
- Обращение на «ты», без форм, которым нужен род.
- Числа ученика в макетах придуманы, на каждом экране стоит пометка «Макет: данные для примера». Тексты задачи, шагов, подсказок, урока и названия всех 41 проверки настоящие: из `src/content/goSprints.js`, `src/content/lessonContent/sprintBookmarksApi.js` и `public/go-sprints/bookmarks-api/check.go`.

**Один и тот же момент во всех макетах.** Модуль 4 · Спринт 1, проект Bookmarks API. Шаги 1 и 2 зелёные, в шаге 3 не проходят три проверки из восьми: `PUT /bookmarks/{id}` отвечает 405. Всего проходят 23 проверки из 41.

## Логика продукта, общая для всех направлений

**Цикл практики.** Код у себя → `go run check.go` → `git push` → сайт показывает, какой шаг стал зелёным и что чинить дальше.

**Правило текущего шага.** Текущий шаг определяется так: первый из шести, в котором есть непройденная проверка в последнем завершённом запуске на GitHub. Шаги до него готовы, шаги после него «впереди», даже если часть их проверок уже проходит (check.go всегда запускает все 41).

**Что сайт может узнать о репозитории.** Проверено 13 октября 2026 года запросами без токена к чужому открытому репозиторию:

| Что нужно | Адрес в API GitHub | Результат |
|---|---|---|
| Последний запуск, commit, итог | `/repos/{o}/{r}/actions/runs` | читается |
| Шаги задания и итог каждого | `/repos/{o}/{r}/actions/runs/{id}/jobs` | читается |
| Аннотации запуска (текст ошибок) | `/repos/{o}/{r}/check-runs/{id}/annotations` | читается |
| Логи запуска | `/repos/{o}/{r}/actions/jobs/{id}/logs` | закрыто, ответ 403 |

Сегодня в `godemy-check.yml` один шаг, поэтому сайт видит только «зелёный или красный». Есть два способа получить больше:

- **Шесть шагов в workflow.** check.go учится проверять один шаг, workflow вызывает его шесть раз. Сайт видит статус каждого шага, но не видит, какая строка упала.
- **Аннотации.** check.go под GitHub Actions печатает `::error title=...::...` для красных строк и короткую сводку по шагам. Сайт видит и шаги, и строки с причиной. У GitHub есть предел: десять аннотаций каждого уровня на шаг.

В макетах показан второй способ. В обоих случаях check.go меняется, значит его нужно перепроверить по AGENTS.md (эталон 41/41, hello-world 3/41, наивный сервер 18-19/41, эталон без мьютекса 38/41), а ученикам со старыми файлами проверки понадобится их обновить: при сдаче файлы сверяются побайтно. Запись аннотаций из check.go в настоящем запуске ещё не проверялась.

**Лимит.** 60 запросов в час с одного адреса. Обновление статуса стоит три запроса, поэтому вместо постоянного опроса стоит кнопка «Обновить», а результат кэшируется по хэшу commit.

## Шаг 2. Четыре направления

Палитра у всех из токенов проекта. Шрифтовая пара у всех одна, Manrope и Roboto Mono, отличается то, что ими набрано.

### 1. «Рабочий стол спринта» (`1-workbench.html`)

Страница CI, которая учит: один экран вместо пяти вкладок, шесть шагов проверки со статусом из последнего push.

```
[ Что делать сейчас: шаг 3 | 23 из 41, лента проверок ]
[ задача · шаг 1 · шаг 2 · ШАГ 3 раскрыт · 4 · 5 · 6 · сдача · ретро ] [ push, файлы ]
```

- **Палитра:** `#eef1fb` фон, `#ffffff` поверхность, `#12141d` текст, `#4b3aeb` действие, `#1b7a4b` проходит, `#b3261e` не проходит.
- **Шрифты:** Manrope 800 для заголовков и счёта, Roboto Mono для команд и строк проверки.
- **Раскладка:** сверху карточка «Что делать сейчас», под ней один вертикальный список от задачи до ретро; справа узкая колонка с историей push.
- **Фирменный элемент:** лента из 41 ячейки, по одной на проверку, сгруппированная по шести шагам.
- **Цикл:** пишешь код у себя, запускаешь проверку, делаешь push, и на сайте зеленеет шаг, а под первым красным написано, что чинить.
- **Что видно первым:** название текущего шага, что именно не прошло, три действия по порядку и кнопка «Обновить статус после push».
- **Чем меряется прогресс:** проверки (23 из 41) и история push с числом пройденных проверок.
- **Объём:** M.
- **Главный риск:** сайт видит только push. Кто отправляет код редко, увидит устаревшую картину.

### 2. «Доска» (`2-board.html`)

Спринт как Kanban-доска, где карточки двигает состояние репозитория.

```
[ GO-1 от роли «Тимлид», закреплена ]
[ Очередь 3 | В работе 1/1 | На проверке 0 | Готово 2 ] [ лист карточки ]
```

- **Палитра:** `#eef1fb` фон, `#f5f6fb` колонка, `#ffffff` карточка, `#e9e6ff` колонка «В работе», `#4b3aeb` действие, `#1b7a4b` готово.
- **Шрифты:** Manrope 800 для названий колонок и карточек, Roboto Mono для красных строк и команд в листе.
- **Раскладка:** закреплённая задача, четыре колонки, справа боковой лист открытой карточки. На телефоне колонки идут списком, «В работе» первой.
- **Фирменный элемент:** карточка с полоской своих проверок, которая переезжает сама, и подпись «Лимит 1» у колонки «В работе».
- **Цикл:** в работе всегда одна карточка; доводишь её проверки до зелёных, после push она уходит в «Готово», из очереди приходит следующая.
- **Что видно первым:** задача GO-1 и единственная карточка в колонке «В работе» с красной меткой.
- **Чем меряется прогресс:** карточки в «Готово» (2 из 6) и проверки внутри карточки.
- **Объём:** L.
- **Главный риск:** шесть карточек, которые идут по порядку и двигаются сами, по сути список; колонка «На проверке» занята около минуты; на телефоне доска не помещается.

### 3. «Сегодня» (`3-today.html`)

Ведомый путь для тех, у кого 30-40 минут: одна карточка, одно дело.

```
[ СЕГОДНЯ, около 35 минут: одно дело, кнопка ]   [ путь курса:  ]
[ неделя: Задача · Изучи · Сделай · Сдай · Ретро ] [ модули точками, ]
[ что уже умеет твой сервис                      ] [ спринты вехами  ]
```

- **Палитра:** `#4b3aeb` карточка «Сегодня», `#ffffff` текст и кнопка на ней, `#eef1fb` фон, `#e9e6ff` подсветка, `#12141d` текст, `#1b7a4b` готово.
- **Шрифты:** Manrope 800 крупным кеглем в карточке, Roboto Mono только для адреса запроса.
- **Раскладка:** одна колонка под телефон; на широком экране путь курса уходит вправо.
- **Фирменный элемент:** сплошная индиго-карточка «Сегодня» с тремя строками плана и минутами.
- **Цикл:** открываешь сайт, видишь одно дело на сегодня с оценкой времени, делаешь его и закрываешь день.
- **Что видно первым:** «Научи сервис менять закладку», около 35 минут, кнопка «Начать с урока».
- **Чем меряется прогресс:** список «Что уже умеет твой сервис» в словах пользователя сервиса, под ним проверки; на пути курса спринты как вехи.
- **Объём:** M. Без статуса из GitHub проще, но тогда блок «что умеет сервис» показать нечем.
- **Главный риск:** оценки времени. Сейчас у шагов проекта их нет, и неверная оценка быстро подрывает доверие к карточке. Экран меняет общий кабинет.

### 4. «Теория рядом с делом» (`4-split.html`)

Две панели: урок и шаг проекта, которому он нужен, всегда на одной странице.

```
[ 1 ✓ | 2 ✓ | 3 сейчас | 4 | 5 | 6 ]
[ урок: текст, пример, «Запустить», квиз | шаг 3: задание, контракт, проверки, команды ]
```

- **Палитра:** `#ffffff` панель урока, `#f5f6fb` панель шага, `#eef1fb` фон, `#4b3aeb` действие, `#e3f4ea` вывод программы, `#fdecea` красная строка.
- **Шрифты:** Manrope для чтения в колонке до 64 знаков, Roboto Mono для кода, вывода и строк проверки.
- **Раскладка:** сверху шесть пар «уроки и шаг», под ними две панели с отдельной прокруткой. На телефоне панели переключаются кнопками «Урок» и «Шаг проекта».
- **Фирменный элемент:** шов между панелями и блок «Что из урока пригодится» в панели шага.
- **Цикл:** читаешь короткий урок, сразу переносишь приём в шаг проекта и проверяешь его командой из соседней панели.
- **Что видно первым:** заголовок урока слева и шаг проекта с красной меткой «5 из 8» справа.
- **Чем меряется прогресс:** шесть пар в верхней полосе и проверки шага в правой панели.
- **Объём:** M. Без статуса из GitHub объём S, проверки тогда показаны списком.
- **Главный риск:** экран по-прежнему начинается с чтения; ученик может пройти уроки подряд и не дойти до кода.

## Что сделать при любом выборе

1. Подключать репозиторий в начале спринта. Сдача становится автоматическим итогом.
2. Считать прогресс спринта в проверках и шагах, а прочитанные уроки показывать вторым планом.
3. Сайт сам называет следующее действие по правилу текущего шага.
4. Уроки открываются перед шагом, которому нужны. Привязка уже есть в `goSprints.js` (`tasks[].lessons`), но покрывает 10 уроков из 11: «Запрос и ответ: что летит по сети» не привязан ни к одному шагу.
5. Ничего не отмечать руками там, где состояние видно из репозитория.
6. Задача GO-1 и контракт открываются с рабочего экрана в одно нажатие.
7. «Продолжить» в кабинете ведёт к текущему шагу спринта.
8. Одно название шага везде. Сейчас карточки называются «Сервер и /health», «Одновременные запросы», «Тесты, README и CI», а отчёт check.go пишет «Сервер запускается», «Надёжность», «Качество».
9. Одна подпись о проверке: статус взят из последнего push, код запускает GitHub, а не Godemy.

## Рекомендация

Первый вариант как экран спринта и третий как вход в курс. Рабочий стол закрывает проблемы 1, 3, 4 и 5 одним экраном. Проблему 2 он закрывает блоком «Теория к этому шагу», то есть привязкой уроков из четвёртого варианта. Карточка «Сегодня» отвечает на вопрос «с чего начать» и ведёт на тот же рабочий стол. Доску стоит оставить в модуле 2 как тему и в GitHub Projects как практику: в спринте из шести последовательных шагов её колонки показывают то же, что и список.

## Открытые вопросы владельцу

1. Для кого курс: верно ли допущение про 30-40 минут после работы и заходы с телефона?
2. Готов ли ты менять `check.go` и `godemy-check.yml` ради статуса по шагам? Это перепроверка эталонов и обновление файлов у тех, кто уже начал спринт.
3. Можно ли убрать ручную доску из спринта, если Kanban остаётся в модуле 2 и в GitHub Projects?
4. Если нравится «Сегодня»: это вход только в курс Go или новый кабинет для всех курсов? Сейчас правило в AGENTS.md требует одной структуры кабинета.
5. Если нравится «Теория рядом с делом»: допустимо ли отступить от одноколоночного экрана урока внутри спринта?
6. Откуда брать минуты для шагов проекта: замер на нескольких учениках или пометка «оценка»?
7. Сдача без вставки ссылки, автоматически при 41 из 41: подходит, или момент «сдаю работу» должен остаться отдельным действием?
8. Формат буткемпа пока пилот на Go. Проектируем экран сразу так, чтобы его могли повторить Python, SQL и QA, или только под Go?

## Чего в макетах нет

- Тёмной темы: в проекте действует решение «светлая тема везде», тёмные токены появятся на шаге системы, если понадобятся.
- Работающих кнопок: макеты статические, раскрываются только блоки `<details>` и переключатель панелей в четвёртом макете.
- Пяти оттенков сверх токенов (контур будущих проверок, «проходит заранее», текст на красном фоне, светлый текст на индиго). На шаге системы их нужно либо добавить в `styles-light.css`, либо заменить существующими.
