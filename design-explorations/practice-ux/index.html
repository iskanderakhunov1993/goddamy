GODEMY Макеты: данные ученика в них для примера

Четыре варианта экрана практики

Все четыре макета показывают один и тот же момент: ученик в середине спринта «Первый HTTP-сервер», два шага проекта Bookmarks API готовы, третий не проходит проверку. Бренд везде один, светлая тема с индиго. Отличаются механика и раскладка.

Варианты

  1. Рабочий стол спринта

    Один экран вместо пяти вкладок, шаги проверки со статусом из репозитория.

    Открыть макет
    Цикл
    Пишешь код у себя, запускаешь go run check.go, делаешь push, и на сайте зеленеет шаг, а под первым красным написано, что чинить.
    Лучше всего подходит, если
    главная цель в том, чтобы ученик в любой момент видел, что сломано и что делать дальше, а вид страницы CI его не пугает.
    Объём работ
    MЭкран из одного списка, подключение репозитория в начале и правка check.go, чтобы GitHub отдавал статус по шагам.
    Главный риск
    Сайт видит только push. Кто отправляет код редко, увидит устаревшую картину, поэтому локальная команда должна оставаться на виду.

  2. Доска

    Kanban-доска, где карточки двигает проверка, а задача от роли «Тимлид» закреплена сверху.

    Открыть макет
    Цикл
    В работе всегда одна карточка. Доводишь её проверки до зелёных, после push она сама уходит в «Готово», из очереди приходит следующая.
    Лучше всего подходит, если
    важнее всего, чтобы спринт был похож на работу в команде, и ученики занимаются в основном с компьютера.
    Объём работ
    LВсё из первого варианта, автомат состояний карточки, боковой лист и отдельная раскладка для телефона.
    Главный риск
    Шесть карточек, которые идут строго по порядку и двигаются сами, по сути список. Колонка «На проверке» занята около минуты после push, а на телефоне четыре колонки не помещаются.

  3. Сегодня

    Одна карточка с одним делом и временем, полоска недели и путь курса.

    Открыть макет
    Цикл
    Открываешь сайт, видишь одно дело на сегодня с оценкой времени, делаешь его и закрываешь день.
    Лучше всего подходит, если
    ученики заходят на 30-40 минут, часто с телефона, и теряются на вопросе «с чего начать». Это вход в курс, а не замена экрана спринта.
    Объём работ
    MПравило выбора дела, новый вход в курс вместо сетки модулей и оценки времени для шагов проекта, которых сейчас нет.
    Главный риск
    Оценки времени. Если «35 минут» два раза окажутся двумя часами, карточке перестанут верить. И экран меняет общий кабинет, одинаковый у всех курсов.

  4. Теория рядом с делом

    Две панели: слева урок с запускаемым примером, справа шаг проекта, которому он нужен.

    Открыть макет
    Цикл
    Читаешь короткий урок, сразу переносишь приём в шаг проекта и проверяешь его командой из соседней панели.
    Лучше всего подходит, если
    главная боль в том, что одиннадцать уроков стоят перед первой строкой кода, а уроки хочется оставить основой курса.
    Объём работ
    MНовый экран урока в спринте и правая панель шага. Без статуса из GitHub делается быстрее, но тогда проверки показаны просто списком.
    Главный риск
    Экран по-прежнему начинается с чтения. Ученик может пройти все уроки подряд и не дойти до кода, а на телефоне панели всё равно видны по одной.

Что общего у всех четырёх

Эти изменения стоит сделать при любом выборе: они и решают пять проблем нынешнего экрана.

  1. Репозиторий подключается в начале спринта. Сдача становится автоматическим итогом, отдельная вставка ссылки в конце исчезает.
  2. Прогресс спринта считается в проверках и шагах: «23 из 41», «2 шага из 6». Прочитанные уроки уходят на второй план.
  3. Сайт сам называет следующее действие. Текущий шаг определяется правилом: первый шаг проверки, в котором есть красная строка.
  4. Уроки привязаны к шагам проекта и открываются перед шагом, которому нужны. Привязка уже записана в данных спринта, одиннадцать уроков подряд перед кодом исчезают.
  5. Там, где состояние видно из репозитория, ученик ничего не отмечает руками: ни карточки доски, ни «готово» у шага.
  6. Задача GO-1 и контракт API открываются с рабочего экрана в одно нажатие.
  7. Кнопка «Продолжить» в кабинете ведёт к текущему шагу спринта, а не к следующему непрочитанному уроку.
  8. У шага одно название везде. Сейчас доска говорит «Одновременные запросы» и «Тесты, README и CI», а отчёт check.go называет те же шаги «Надёжность» и «Качество».
  9. Везде одна подпись о проверке: статус взят из последнего push, код запускает GitHub, а не Godemy.

Что стоит за «статусом из репозитория»

  • Сегодня сайт видит только общий итог запуска: зелёный или красный. В godemy-check.yml один шаг, go run check.go.
  • Чтобы показывать шаги и красные строки, check.go должен под GitHub Actions печатать аннотации, а сайт читать их по адресу /repos/{owner}/{repo}/check-runs/{id}/annotations.
  • Проверено 13 октября 2026 года на чужом открытом репозитории без токена: список запусков, шаги задания и аннотации читаются, логи запуска закрыты (ответ 403). На репозитории с файлами Godemy это ещё не проверялось.
  • После правки check.go его нужно перепроверить по правилам из AGENTS.md, а ученикам со старыми файлами проверки понадобится их обновить.
  • Лимит GitHub прежний: 60 запросов в час с одного адреса. Одно обновление статуса стоит три запроса, поэтому в макетах стоит кнопка «Обновить», а не постоянный опрос.

Что бы выбрал дизайнер

Первый вариант как экран спринта и третий как вход в курс. Рабочий стол закрывает четыре проблемы из пяти одним экраном. Карточка «Сегодня» отвечает на оставшийся вопрос «с чего начать» и ведёт на этот же экран. Из четвёртого варианта стоит взять привязку уроков к шагам, она уже есть в первом макете в блоке «Теория к этому шагу». Доску лучше оставить в модуле 2 как тему и в GitHub Projects как практику: в спринте из шести последовательных шагов её колонки показывают то же, что и список.
