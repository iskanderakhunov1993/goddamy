# Журнал решений

Новые решения — сверху. Формат: дата, решение, почему, источник. Решения ниже перенесены из уже существующих документов; дата — дата документа или коммита, где решение зафиксировано.

## 2026-10-12 — Курс Go перестраивается в буткемп
- Решение: сначала общая база (Старт → Как работают команды → База Go), потом спринты: один спринт — один проект — около недели. Порядок спринта повторяет рабочую неделю: задача от тимлида → материалы и пример соседней команды → работа по доске → сдача по ссылке → ретроспектива. Правило «6 модулей × 5 тем × 5 уроков» отменено: объём модуля определяет задача.
- Почему: решение владельца. После курса ученик должен уметь делать рабочие задачи руками; формат взят из его опыта работы в команде. Проекты подбираются по мотивам roadmap.sh, от простых к сложным и максимально разные.
- Пилот: модуль «Как работают команды» и спринт «Первый HTTP-сервер». Остальные спринты — в `docs/go-bootcamp-program.md`.

## 2026-10-12 — Задача приходит от роли, без персонажей
- Решение: задача спринта оформлена как тикет от роли («Тимлид»). Имён, вымышленной компании, сквозного сюжета и иллюстраций героев по-прежнему нет.
- Почему: решение владельца. Формат «задача от руководителя» нужен, чтобы спринт был похож на работу, а запрет на персонажей (2026-09) остаётся в силе.

## 2026-10-12 — Сдача спринта: проверка в GitHub Actions и ссылка на репозиторий
- Решение: ученик запускает `check.go` у себя, тот же скрипт выполняет GitHub Actions в его репозитории, сайт по ссылке читает открытый API GitHub и закрывает спринт только при зелёной проверке и неизменённых файлах проверки.
- Почему: у сайта нет сервера, чтобы запускать чужой код, а одной ссылки без проверки мало. Заодно ученик с первого спринта работает с CI.
- Ограничения: лимит GitHub — 60 запросов в час с одного адреса без входа; проверяется поведение программы, а не качество кода, живого ревью нет.

## 2026-10-11 — Единый стиль: светлый с индиго
- Решение: весь продукт приводится к светлой теме с акцентом `#4b3aeb`. Тёмно-синий с жёлтым лендинг и серо-зелёный тренажёр — наследие; при любой правке сводить их к светлому стилю. Главное действие — сплошная кнопка в индиго.
- Почему: решение владельца по итогам UX-аудита (три визуальных языка в одном продукте).

## 2026-10-11 — Обращение на «ты» везде
- Решение: ко всем ученикам, включая взрослые курсы, тренажёры, профиль и подписку, обращаемся на «ты».
- Почему: решение владельца; раньше «ты» и «вы» смешивались на одном экране.

## 2026-10-11 — Одна формулировка про деньги и честный объём
- Решение: уроки, тренажёры и проекты бесплатны; подписка открывает только скачивание сертификата. В числах — только написанные уроки (в Go 66 и один проект); модули без уроков помечаются «В разработке».
- Почему: лендинг, страница подписки и кабинет противоречили друг другу и обещали больше, чем есть.

## 2026-10-09 — Защита ветки main
- Решение: в main только через PR; обязательна зелёная проверка `check` (CI), ветка PR должна быть актуальной с main; force-push и удаление запрещены; правила действуют и для владельца. Одобрение ревьюера не требуется (владелец работает один).
- Почему: решение владельца при настройке командного процесса.

## 2026-10-09 — Продакшен — godemy.vercel.app
- Решение: основной адрес пока godemy.vercel.app; godemy.ru привязан в Vercel, но не используется. Деплой — вручную `vercel --prod`, только после «да» владельца.
- Почему: решение владельца.

## 2026-10-06 — Детские курсы учат на реальных задачах, а не на играх
- Почему: решение владельца. Задачи из жизни школьника (деньги, оценки, расписание, словарный диктант) дают понятный смысл; всё работает в браузере без установки.
- Источник: AGENTS.md («Kids direction»).

## 2026-10-04 — Проект каждого курса — реальная практика у ученика с проверкой скриптом
- Почему: решение владельца. Ученик делает проект на своём устройстве и запускает `check.*`; ручные чек-листы допустимы только там, где машинная проверка невозможна (YouTube), и это говорится прямо.
- Источник: AGENTS.md («Core principle»).

## 2026-10-02 — Непроверенный проект не выдаётся за работающий
- Почему: проект «Kafka в kind» не запускался на реальном кластере (нет Docker), поэтому показан как «в разработке».
- Источник: AGENTS.md (Kubernetes и Kafka).

## 2026-09 — Python выполняется по-настоящему (Pyodide), без проверки подстрокой
- Почему: прежняя «проверка» `code.includes(token)` не была выполнением кода; её нельзя было выдавать за тренажёр.
- Источник: AGENTS.md (Python).

## 2026-09 — Без вымышленной компании, сюжета и персонажей
- Почему: уроки учат на настоящем проекте ученика, а не через диалоги в выдуманном офисе. Персонажей и «Bit Tech» не возвращать (это проверяет тест `course-content.test.mjs`).
- Источник: AGENTS.md.

## 2026-09 — Прогресс: localStorage как кэш + Supabase Postgres, вход необязательный
- Почему: снять ограничение MVP «прогресс пропадает после обновления» (README, FINAL_AUDIT), не заставляя регистрироваться.
- Источник: AGENTS.md (Persistence), `supabase/migrations/20260907223236_user_state.sql`.

## 2026-08-12 — Курс и тренажёр бесплатны, подписка — только за сертификат
- Почему: позиционирование «практика прежде всего».
- Источник: AGENTS.md; FINAL_AUDIT.md («будущие проекты без платной блокировки», убрана иконка замка).

## 2026-08-12 — Кнопки курса ведут прямо в кабинет, без промежуточной страницы
- Почему: лишний шаг между CTA и кабинетом мешал.
- Источник: design-qa.md («Unified course cabinet»), AGENTS.md.

## 2026-08-12 — Единая структура кабинета и светлая тема кабинетов
- Почему: одинаковая навигация во всех курсах; тёмный лендинг и светлые кабинеты — известное расхождение, которое нужно сводить, а не углублять.
- Источник: design-qa.md, AGENTS.md.

## 2026-08 — Практика живёт внутри курса, а не в общей навигации
- Почему: тренажёр открывается из контекста своего курса.
- Источник: design-qa.md (SQL и Python extension).
